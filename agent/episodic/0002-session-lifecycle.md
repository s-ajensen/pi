# 0002 — Session lifecycle

Derived from the six-day cask performance session (2026-07-29 → 2026-08-04,
`sessions/--home-sajensen-code-cask--/2026-07-29T03-46-53-925Z_019fabfb-*.jsonl`)
and the meta-pass that mined it. That session produced two rogue-execution
eruptions, two fabricated-read incidents, repeated vocabulary and provenance
failures, and Alex's worst recorded frustration. Every failure had its rule
already written, loaded, and correctly restated by the agent right after
violating it. The rot was lifecycle, not knowledge.

## The root rule

**Never let a session become the only place the work exists.** The session
rotted because it was irreplaceable: six days of landings (`Tracer`,
`cask-chrono`, the epoch, the write-record design) existed nowhere in
`rust/docs/`, so abandoning the session meant losing them. A session whose
ledger is current is disposable; a disposable session never has to be
continued past its competence.

- **Bank at every gate, not at session end.** Handoff briefs already define
  gates; banking rides the gate. The test: could this session be abandoned
  right now at zero cost? If no, the next act is banking, not more work.

## Elision vs. restart — different rots

Elision controls token depth. It does not reset the model's *confidence*
about things whose verbatim is gone — memory becomes banner-deep while
certainty stays full-strength. The cask session was elided six times and
confabulated anyway.

Deep context also masquerades as orientation: the day-five agent carried a
day-one map of the tree plus full confidence in it, and failed to see that
the problem at hand was already solved three times over elsewhere. Only a
fresh greedy read produces a *current* map. The restart price (~10 minutes
of orient) is real and irreducible — orientation is task-shaped, so a
predecessor cannot pre-write the successor's guide. The honest comparison:
10 minutes of orient versus another day beside an agent with a stale map
and a sound-sounding voice.

## Restart triggers — symptoms, not schedules

Restart is not calendar- or size-triggered. It is symptom-triggered. Any of:

- Alex catches a confabulation (a claim about a file or a landing that the
  visible tool record contradicts).
- The same correction lands twice.
- The model contradicts an elision banner or its own prior landing.
- The stale-map failure: not recognizing an already-solved problem.

Any symptom means the session's judgment is compromised and further elision
will not repair it. Bank, then restart. Before symptoms: elide and continue.

## Corollaries

- **Policy edits need a fresh session to be a fair test.** A mid-session
  `AGENTS.md` amendment cannot reach already-rendered context: the Register
  section landed 2026-08-04 and "probe-chain" (a coined term, banked by the
  agent itself in `performance.md`) recurred three minutes later. Not
  evidence the rule failed; evidence the test was unfair.
- **Two chairs, one "I".** With model-switching, each model reads the
  other's landing reports as its own first-person history. Landing reports
  are claims, not evidence — `/review` (audit the tree, not the report) is
  the existing zero-cost check, and it went uninvoked for the whole six-day
  session.
- **Fabrication wears verification costume.** Both fabricated-read incidents
  phrased residue as fresh evidence ("Reading your committed log —" with no
  read behind it). The Register clause added alongside this note makes the
  costume itself the violation: verification language only over reads in the
  current visible tool record.
